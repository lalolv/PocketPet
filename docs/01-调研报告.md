# PocketPet 调研报告

> 调研时间：2026-08-08
> 目标：为"基于 LLM Agent 的宠物养成服务系统（Golang）"做技术调研，为选型与设计提供依据。

## 1. 需求要点回顾

1. 只实现最基础的宠物核心功能（属性、成长、交互）。
2. 通过插件 / Skill 等机制扩展功能。
3. Golang 实现，可跨平台编译，未来可跑在嵌入式设备上。
4. 只提供接口服务（不实现 UI），可对接网页 / 桌面 / 移动端 / 物理设备屏幕等任意前端。
5. 考虑引入 Google 官方 Agent SDK 的 Go 版本。
6. 支持多种 LLM 提供商，兼容 OpenAI 接口。

## 2. Google Agent SDK（ADK）Go 版调研

### 2.1 现状

Google 官方的 Agent Development Kit 已有 Go 语言版本：

- 仓库：[github.com/google/adk-go](https://github.com/google/adk-go)
- 模块路径：`google.golang.org/adk`，当前主版本为 **v2**（[pkg.go.dev/google.golang.org/adk/v2](https://pkg.go.dev/google.golang.org/adk/v2)），官方文档站 [adk.dev](https://adk.dev/get-started/go/) 已提供 Go 快速上手，ADK Go 2.0 引入了基于图的 workflow agent、并行/循环执行原语、Human-in-the-Loop 工具确认等能力。
- 与 Python / TypeScript / Java 版 ADK 保持统一的 API 设计（code-first、model-agnostic）。

注意社区中存在若干同名/仿名项目（如 `KennethanCeyer/adk-go`、`agent-protocol/adk-golang`），**非官方，不应采用**。认准 `google/adk-go` 与 `google.golang.org/adk`。

### 2.2 与本项目相关的关键能力

| 能力 | 包路径 | 对本项目的意义 |
|---|---|---|
| LLM Agent | `agent/llmagent` | 宠物的"大脑 / 人格"，驱动对话与自主行为 |
| 模型抽象 | `model`（`model.LLM` 接口） | 多提供商接入的统一抽象 |
| Gemini 接入 | `model/gemini` | Google 系模型 |
| OpenAI 接入 | `model/openaimodel`（v2.1.0 起，**Experimental**） | 兼容 OpenAI 接口的模型提供商，见 2.3 |
| 函数工具 | `tool/functiontool` | 把"喂食 / 玩耍 / 清洁"等宠物操作暴露给 Agent |
| Skill 工具集 | `tool/skilltoolset`（含 `skilltoolset/skill`） | 以 SKILL.md 形式加载技能，**正是需求 2 要的扩展机制** |
| MCP 工具集 | `tool/mcptoolset` | 可接入任意 MCP Server，进一步扩展能力 |
| 插件钩子 | `plugin`（如 `plugin/retryandreflect`） | Agent 生命周期钩子，可做护栏、自愈重试等 |
| Runner / Session / Memory | `runner`、`session`、`memory` | 会话与长期记忆管理 |
| REST API 暴露 | `server` + `launcher/web/api` | 官方自带的 REST API server，可参考但本项目会自建业务 API |
| A2A 协议 | `server/adka2a`、`launcher/web/a2a` | 未来把宠物作为 A2A Agent 暴露给其它 Agent |
| Workflow Agent | `workflowagents/*`、`workflow` | 未来编排复杂行为（如每日例行） |
| 遥测 | `telemetry` | OpenTelemetry 支持 |

### 2.3 OpenAI 兼容接入（openaimodel）

依据官方文档 [OpenAI models for ADK agents](https://adk.dev/agents/models/openai/)：

- `openaimodel` 实现 `model.LLM` 接口，**面向 OpenAI Responses API**。
- `ClientConfig` 支持 `APIKey` / `BaseURL`，缺省时回落到环境变量 `OPENAI_API_KEY` / `OPENAI_BASE_URL`。
- 官方明确支持用 `BaseURL` 指向 OpenAI 兼容端点（如 Ollama、LM Studio、vLLM）。
- 支持：文本生成（流式/非流式）、Function Calling、`OutputSchema` 结构化输出、推理模型。
- 限制：**仅文本**（不支持图片/音频输入）；只支持函数工具（不支持各家内置工具）；部分生成参数会报错而不是被忽略。

**风险点**：`openaimodel` 面向 OpenAI **Responses API**，而很多"OpenAI 兼容"的第三方端点（部分国产模型网关、老旧 vLLM 部署）只实现了 **Chat Completions API**。备选方案：

- 第三方适配器 [huytd/adk-openai-go](https://github.com/huytd/adk-openai-go)：基于 Chat Completions 的 ADK 模型适配器，支持任意 OpenAI 兼容 API。
- 自研一个薄适配层实现 `model.LLM`（接口本身很小），按 provider 选择 Responses 或 Chat Completions。

## 3. 其他候选技术调研（对比用）

| 方案 | 说明 | 评价 |
|---|---|---|
| **Google ADK Go（官方）** | 见上文 | 符合需求 5；官方背书、能力全（tools/skills/MCP/A2A）；缺点：较年轻，v2 API 仍在演进，openaimodel 标记 Experimental |
| langchaingo | Go 版 LangChain | 社区项目，模型接入多，但 Agent 抽象弱于 ADK，无 skills/plugin 体系 |
| 自研 Agent 循环 | 自己写 tool-call 循环 + OpenAI SDK | 可控、依赖最少，但要重复造 session/memory/skills/A2A 的轮子，违背"引入官方 SDK"的方向 |
| inference-gateway/adk | 第三方 A2A ADK | 面向 Inference Gateway 生态，非 Google 官方，不采用 |

## 4. 嵌入式与跨平台考量

- 纯 Go 依赖优先，避免 cgo：SQLite 驱动选 `modernc.org/sqlite`（纯 Go 实现）而非 `mattn/go-sqlite3`（cgo），保证 `GOOS/GOARCH` 交叉编译（含 ARM 嵌入式）无障碍。
- ADK Go 为纯 Go，无平台限制；网络仅依赖标准库 HTTP。
- 二进制形态：单进程常驻服务（daemon），配置文件 + 本地 SQLite，资源占用低，适合树莓派级别的设备。

## 5. 调研结论

1. **采用 Google 官方 ADK Go v2**（`google.golang.org/adk/v2`）作为 Agent 框架，满足需求 5，且其 `skilltoolset` / `mcptoolset` / `plugin` 直接支撑需求 2 的扩展体系。
2. **多模型通过 `model.LLM` 抽象接入**：Gemini 走 `model/gemini`；OpenAI 及兼容端点走 `model/openaimodel`（配置 `BaseURL`）；对只支持 Chat Completions 的端点预留自研薄适配层。满足需求 6。
3. **业务 API 自建**（REST + SSE），不依赖 ADK Web UI；核心宠物逻辑（属性衰减、成长）用确定性 Go 代码实现，LLM 负责人格化表达与自主行为决策，保证养成逻辑可测试、可控。
4. 主要风险：ADK Go v2 较新、openaimodel 为 Experimental → 通过"薄适配层 + 接口隔离"把 ADK 相关代码收敛在 `internal/agent` 内，未来可替换。
