# 宠物状态管理器（PetState Manager）

> 版本：v1.0  
> 前置：[`03-架构设计方案.md`](03-架构设计方案.md) §7.1（本文件为权威细则）  
> 实现包：`internal/petstate`

## 0. 动机

补丁式互斥（散落 `if Sleeping`、内存占用表、时序约定）无法根除：

- Sleeping / 玩法占用 / 插件行程三源可撕裂；
- GetPet → 判断 → Begin 存在 TOCTOU；
- AutoSleep 与探险竞态依赖调用顺序。

**根治**：一只宠同一时刻只有一个写入口；读到原子快照；切换是带守卫的 Transition。

## 1. 分层模型

| 层 | 内容 | 互斥 | 写入方 |
|---|---|---|---|
| Life | incubating / alive / dead | 是 | Manager（经诞生/死亡路径） |
| Stage | egg→adult | 正交 | 领域 Tick/Care/Adjust |
| Conditions | hungry/dirty/sleepy/sick/sad | 可叠加 | Stats 派生（边沿事件） |
| Activity | idle / sleeping / 插件 kind | Alive 下恰一个 | **仅 Manager.Apply** |
| Intents | 排队意图（如 sleep） | 非活动 | Manager（忙时入队，回 idle 消费） |

`Sleepy ≠ Sleeping`：前者是条件态，后者是活动态。

## 2. 冲突策略

**拒绝切换 + 意图排队**（定死）：

| 场景 | 行为 |
|---|---|
| Idle + sleepy / IntentSleep | → sleeping |
| Adventuring + AutoSleep | 不抢占；登记 IntentSleep；结束回 idle 后若仍困/有意图 → sleeping |
| Sleeping 或（Idle 且 sleepy） | 拒绝 → adventuring |
| 已是目标 Activity | `ErrAlready`（非幂等成功） |
| 重启恢复 | `Restore`，不走普通 Apply |

## 3. API

包：`internal/petstate`。

- `View(ctx, id) (Snapshot, error)`
- `Apply(ctx, id, Transition) (Result, error)` — **唯一**活动切换入口
- `RegisterKind(ActivityKind)` — 插件 Init 注册
- `Restore(ctx, id, kind, owner)` — 进程重启对齐占用

`tick.Engine` 的 Care / Adjust / 旧 Begin·End 薄封装转调 Manager。  
`plugin.PluginContext` 暴露 `View` / `Apply` / `RegisterActivity`。

## 4. 插件 ActivityKind

```text
Name / Owner
CanEnter(before Snapshot) error
AfterLeave(ctx, id, reason) error   // 清插件私有表
```

私有表只存行程细节，不得充当「是否在忙」的全局真相。

## 5. 持久化

`Pet` JSON：`activity`、`activity_owner`、`state_seq`、`intents`。  
`Pet.Sleeping` 派生于 `activity==sleeping`（读兼容）；写只经 Apply。

## 6. 竞态硬规则

1. 每宠单锁；Apply/Care/Adjust/Settle 同锁。
2. 禁止 TOCTOU：插件只调 Apply。
3. OnCommit 同锁；失败回滚 Activity。
4. emit 持锁时订阅方禁止重入同宠写路径。
5. 重启：Activity 从 DB 恢复；与插件 run 不一致则自愈（abort→idle）。

## 7. 叙事层（narrate）

> 实现包：`internal/narrate`

**Manager 管能不能切换；Narration 管能不能这么说。**

主人可见文案（proactive / Agent Outcome / 主对话）必须经 `narrate.Policy(trigger, Context)`，复述 Snapshot 或 Apply 结果：

- 条件事件（如 `pet.sleepy`）≠ 活动完成；「我去睡了」只在已 sleeping / `EffectSlept` / `fell_asleep`。
- `EffectQueuedSleep`：只准说「好困、忙完再睡」，禁止晚安/已入睡口吻。
- 主对话注入 `ChatConstraint`：不得与当前 Activity/Intents 矛盾。

## 8. 验收用例

- 并发两次 adventure_start：恰一次成功，精力只扣一次。
- sleepy 与 start 任意交错：先睡拒出门，或先探后 Intent 排队回来再睡；无「困了却走完图」的活动撕裂。
- 探险中 sleepy 主动消息：不得在 `fell_asleep` 前声称已睡/晚安结束。
- 重启后 Activity 与 run 一致或自愈。
