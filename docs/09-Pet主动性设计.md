# 09 - Pet 主动性设计：心愿、承诺与故事弧

> 主动性不是让宠物更频繁地发消息，而是让玩家相信：
> **即使没有收到指令，宠物也会形成愿望、做出选择、推进生活，并留下可被发现的结果。**
>
> 本方案延续项目铁律：**数值在 Go，灵魂在 LLM**。
> LLM 负责理解情境、形成动机、规划、表达和反思；Go 负责权限、状态、资源、结算、持久化和节奏护栏。

## 0. 现状与问题

当前 `internal/proactive` 是一个可靠的状态驱动行为器：

- 饿、脏、困、病、心情低落、睡醒等领域事件触发主动消息；
- 精力不足时自动入睡，睡饱后自动醒来；
- LLM 只生成第一人称文案，不参与数值规则；
- 文案通过 `narrate.Policy` 约束，不能臆造实际活动状态。

它解决了“宠物会不会主动开口”，但还没有解决“宠物是否拥有自己的生活”：

1. **动机来源单一**：主动行为几乎都来自负面状态阈值，容易退化成告警通知。
2. **LLM 参与太晚**：Go 已经决定发生什么，LLM 只负责换一种说法。
3. **缺少连续目标**：没有跨会话存在的愿望、计划和未完成事项。
4. **缺少自主结果**：宠物很少在主人离开期间主动推进玩法或改变世界。
5. **缺少玩家选择**：消息通常只需要主人执行固定照顾动作，难以形成协商、帮助、拒绝和意外结果。
6. **缺少节奏设计**：阈值触发天然容易重复，而真正有趣的主动事件需要高潮、低谷和留白。

因此，本方案不继续扩大状态告警，而是新增一套游戏性主动循环。

## 1. 设计目标

### 1.1 核心体验

玩家应逐步产生以下感受：

- 宠物有自己当下想做和长期在意的事；
- 宠物的选择符合其人格、记忆、关系和当前环境；
- 宠物可以先自己行动，遇到分歧或困难时再找主人；
- 主人的回应会被记住，并影响之后的行为，但不会变成机械好感按钮；
- 玩家离开后世界仍在前进，回来时能发现新的痕迹；
- 不同宠物在相同状态下也会做出明显不同的选择。

### 1.2 非目标

- 不让 LLM 直接修改属性、活动状态、关系值、物品或掉落；
- 不把每个 tick 都变成一次 LLM 调用；
- 不用海量通知伪装主动性；
- 不让宠物未经许可执行高风险、不可逆或具有外部副作用的行为；
- 不因 LLM 未配置或调用失败破坏基础养成闭环；
- 不用情感勒索惩罚长期未上线或拒绝请求的玩家。

## 2. 设计参考

### 2.1 《模拟人生》：性格化自治与冷却

自治行为需要同时考虑性格、偏好、环境和重复冷却。EA 对《模拟人生 4》自治行为的调整集中在减少过度重复、让喜好决定行为候选、让特定性格拥有特殊倾向。这说明“可预测的人格一致性”和“偶尔发生的意外”必须同时存在。

参考：[EA - The Sims 4 Autonomy Improvements](https://www.ea.com/en/games/the-sims/the-sims-4/news/laundry-list-march-10-2026)

### 2.2 《动物森友会》：居民主动创造社交理由

居民会跑向玩家、请求帮助、发送信件和礼物，并在玩家不在线时继续自己的日常。主动行为的价值不在于提醒玩家填数值，而在于持续制造关系事件和再次见面的理由。

参考：[Nintendo - How To Be a Good Neighbor](https://play.nintendo.com/news-tips/tips-tricks/animal-crossing-new-horizons-neighbors-tips/)

### 2.3 Tamagotchi：呼唤、照顾历史与成长结果

宠物会主动呼唤玩家，玩家长期如何回应会影响成长结果。关键不是一次喂食奖励，而是“共同经历塑造了这只宠物”。

参考：[Bandai - Original Tamagotchi](https://www.bandai.com/original-tamagotchi-neon)

### 2.4 《Left 4 Dead》：导演控制体验节奏

AI Director 根据玩家压力制造强弱交替，而不是持续堆叠事件。虚拟宠物同样需要“生活导演”控制请求、惊喜、沉默和故事高潮的比例。

参考：[Valve - Replayable Cooperative Game Design: Left 4 Dead](https://steamcdn-a.akamaihd.net/apps/valve/2009/GDC2009_ReplayableCooperativeGameDesign_Left4Dead.pdf)

## 3. 总体方案

新增“心愿—承诺—故事弧”三层模型：

1. **心愿（Desire）**：LLM 根据人格、记忆和机会提出“我现在为什么想做什么”。
2. **承诺（Commitment）**：Go 从候选心愿中选出值得持续推进的目标，并持久化执行状态。
3. **故事弧（Story Arc）**：重要承诺被展开为萌芽、尝试、阻碍、介入、结果和反思等节点。

完整循环：

```text
领域事件 / 醒来 / 活动结束 / 定时反思
                    │
                    ▼
          构造只读情境与机会目录
                    │
                    ▼
          LLM 生成结构化候选心愿
                    │
                    ▼
       Go 校验 → 评分 → 限流 → 持久化
                    │
                    ▼
        自主执行 / 先告知 / 请求主人确认
                    │
                    ▼
        Engine / 插件工具执行确定性动作
                    │
                    ▼
          领域事件、进度、结果与痕迹
                    │
                    ▼
        LLM 叙事与反思 → 日记 / MEMORY
```

## 4. 心愿系统

### 4.1 心愿的来源

一次思考应向 LLM 提供以下上下文：

- `PET.md`：身份、物种和成长阶段；
- `SOUL.md`：人格、喜好、恐惧、习惯和表达风格；
- `MEMORY.md` 与近期日记：重要关系、承诺和未完事件；
- 当前属性、活动、排队意图和最近领域事件；
- 好友关系及对方当前是否可互动；
- 当前探险地图、地点、时间、季节等世界情境；
- 已启用插件提供的可执行机会；
- 最近已做过的动作及其冷却；
- 主人最近的互动方式和明确偏好；
- 当前有效承诺，避免反复重开相同目标。

### 4.2 心愿类型

建议首期支持以下类型：

| 类型 | 说明 | 示例 |
|---|---|---|
| `need` | 对身体或情绪状态的主观反应 | “我想找个安静的地方休息” |
| `curiosity` | 对世界、地点、事物的好奇 | “我想看看岛屿北边有什么” |
| `social` | 拜访、送礼、和好、竞争、分享 | “球球最近不开心，我想去看看它” |
| `bond` | 与主人建立共同经历 | “我想和主人给秘密基地取名” |
| `project` | 跨多个步骤的个人项目 | “我想画完一张探险地图” |
| `growth` | 克服弱点或强化自我认同 | “我想试着独自走完一段路” |
| `ritual` | 形成重复但有意义的习惯 | “每晚交换一件开心的小事” |
| `surprise` | 暂时对主人隐藏的准备 | “悄悄给主人做一份礼物” |

### 4.3 结构化输出

LLM 只生成候选提案，不直接执行：

```go
// DesireProposal 是 LLM 生成、尚未被系统接受的心愿候选。
type DesireProposal struct {
    Kind            string         `json:"kind"`
    Desire         string         `json:"desire"`
    Reason          string         `json:"reason"`
    Target          Target         `json:"target"`
    Urgency         float64        `json:"urgency"`
    Horizon         string         `json:"horizon"`
    Autonomy        AutonomyLevel  `json:"autonomy"`
    Steps           []ProposedStep `json:"steps"`
    SuccessMeaning  string         `json:"success_meaning"`
    FailureMeaning  string         `json:"failure_meaning"`
    Evidence        []string       `json:"evidence"`
}
```

`Evidence` 必须引用输入中真实存在的人格、记忆、关系或机会，便于 Go 丢弃无来源的提案。

示例：

```json
{
  "kind": "project",
  "desire": "找到昨晚梦里的蓝色贝壳",
  "reason": "那个梦让我想起主人以前讲过的海边",
  "target": {"type": "zone", "id": "coast"},
  "urgency": 0.42,
  "horizon": "2d",
  "autonomy": "announce_first",
  "steps": [
    {"action": "adventure_start", "args": {"preferred_zone": "coast"}},
    {"action": "inspect_discovery", "args": {}},
    {"action": "ask_owner_for_help", "when": "blocked"}
  ],
  "success_meaning": "我会觉得自己更勇敢，也会得到一件纪念物",
  "failure_meaning": "我可能发现真正想要的是和主人分享旅程",
  "evidence": ["dream:blue-shell", "memory:owner-talked-about-sea"]
}
```

### 4.4 触发时机

不要在每次 tick 调用 LLM。采用分层触发：

| 层级 | 触发 | 是否调用 LLM |
|---|---|---|
| 生理反射 | 饥饿、困倦、疾病、自动睡醒 | 否；沿用现有 `proactive` |
| 短思考 | 醒来、活动结束、聊天结束、重要事件 | 是；有冷却且抖动调度 |
| 空闲思考 | 空闲 2～6 小时，具体时间随机 | 是；已有足够承诺时跳过 |
| 日终反思 | 入睡后的梦境整理 | 是；复盘而非产生大量新目标 |
| 全局导演 | 世界长期无事件或强度过高 | 可选；优先用 Go 规则选择机会 |

## 5. 承诺系统

### 5.1 为什么需要承诺

直接让 LLM 每次自由产生行为，会导致目标漂移：今天想找贝壳，下一次调用又想写诗。承诺把生成式动机转化为可持续的游戏状态。

每只宠物建议最多同时拥有：

- 1 个即时欲望：几分钟到数小时；
- 1 个个人项目：1～3 天；
- 1 个长期愿望：跨成长阶段存在。

新提案不能无条件覆盖已有承诺。只有完成、明确放弃、过期、世界条件永久失效或主人协商改变目标时，才能结束或替换。

### 5.2 确定性评分

由 Go 计算候选分数：

```text
score =
    personality_match
  + memory_relevance
  + current_need
  + relationship_relevance
  + world_opportunity
  + unfinished_arc_bonus
  + controlled_randomness
  - repetition_penalty
  - interruption_cost
  - resource_risk
  - conflict_penalty
```

要求：

- 分数项均可记录，便于测试与调试；
- `controlled_randomness` 只用于相近候选之间的变化，不得覆盖硬约束；
- 对同一动作、对象、主题分别设置冷却；
- 性格影响权重，而不是写死行为结果；
- 资源不足、活动冲突和权限不足直接拒绝，不交给 LLM 辩解。

### 5.3 持久化状态

```go
// Commitment 是已经被接受并持续推进的目标。
type Commitment struct {
    ID             string
    PetID          string
    Kind           string
    Desire         string
    Reason         string
    Status         string // active / waiting_owner / blocked / completed / abandoned / expired
    CurrentBeat    int
    Progress       float64
    Autonomy       AutonomyLevel
    Target         Target
    CreatedAt      time.Time
    UpdatedAt      time.Time
    ExpiresAt      *time.Time
    LastActionAt   *time.Time
    OwnerResponse  string
    Version        int64
}
```

运行状态存 SQLite。可以额外生成只读的 `ACTIVE.md`，让主人和 Agent 看见宠物当前在意的事，但执行真相仍以 SQLite 为准。

## 6. 自主权限模型

### 6.1 三级权限

| 等级 | 行为 | 规则 |
|---|---|---|
| `autonomous` | 写日记、休息、散步、拜访、练习已有技能 | 可直接执行，完成后留下痕迹 |
| `announce_first` | 消耗普通精力探险、开始个人项目、改变短期作息 | 先告知；无需等待主人在线 |
| `ask_first` | 稀缺资源、外部 MCP、副作用行为、重大关系决定 | 必须获得主人确认 |

权限由 Go 侧能力目录声明，LLM 只能提出更保守的等级，不能自行降低权限要求。

### 6.2 永远由 Go 控制的事项

- 属性增减、经验、成长、生死；
- 活动态和 `petstate.Manager` 转换；
- 掉落、物品、地图与关系数值；
- 资源消耗、冷却和成功概率；
- 外部 MCP 是否允许调用；
- 高风险和不可逆行为的审批；
- 事件是否落库以及玩家可见事实。

LLM 可以决定“为什么想做”和“遇到结果如何理解”，不能决定“规则上已经成功”。

## 7. 故事弧

重要承诺展开成 3～6 个节点：

1. **萌芽**：宠物产生想法，可只在行为或日记中留下线索；
2. **尝试**：宠物自主采取第一步；
3. **阻碍**：遇到资源、路线、关系或内心冲突；
4. **玩家介入**：请求建议、陪伴、许可或帮助；
5. **结果**：成功、失败、妥协或意外发现；
6. **反思**：结果进入日记、长期记忆，必要时影响 SOUL 或 Skill。

故事节点不是 LLM 随意宣告的剧情事实。LLM 先从受控模板中选择节点意图，Go 创建相应机会并执行确定性结算，LLM 再解释结果。

### 7.1 示例：梦里的蓝色贝壳

1. 团团梦见海边有一枚蓝色贝壳，醒来后形成寻找它的心愿；
2. 系统发现当前地图存在海岸带，允许团团自主开始一次探险；
3. 路线出现分支，团团根据胆量选择自己决定，或向主人请求建议；
4. 主人不在线时，承诺不会卡死，超时后按性格和风险规则自主选择；
5. 掉落由探险插件结算，可能找到贝壳，也可能只找到蓝色石头；
6. LLM 根据真实结果反思：“也许我想找的不是贝壳，而是想把旅途带回来给你看”；
7. 日记记录经历，反复完成类似挑战后可能沉淀“海岸探索”Skill 或推动胆量相关人格演化。

失败同样应产生内容，而不是只有成功才有故事。

## 8. 主动玩法类型

### 8.1 个人项目

- 给主人或朋友准备礼物；
- 写诗、画地图、编故事；
- 建立收藏或观察记录；
- 策划生日惊喜；
- 为地点、物品或共同经历命名；
- 研究某个反复出现的梦。

项目产物可以是受控物品、收藏卡或可读文件。LLM 负责内容，Go 负责产物类型、获得条件和归属。

### 8.2 主动社交

- 主动拜访、送信和送礼；
- 冲突后尝试和好；
- 邀请朋友共同探险；
- 分享传闻、梦和发现；
- 形成昵称、共同仪式、竞争或敬佩；
- 根据历史互动表现出不同社交距离。

关系动机和叙事由 LLM 生成，好感度和互动次数仍由 `friends` 插件结算。

### 8.3 反向照顾主人

- 记住主人提到的考试、旅行、生日或困难；
- 到约定日期主动询问结果；
- 主人反复表达疲惫时提议安静陪伴；
- 为主人准备一段回家后再揭示的故事；
- 根据共同记忆创造问候、小游戏或纪念仪式。

涉及日历、邮件等外部信息时，必须经 MCP 权限和 `ask_first` 规则控制。

### 8.4 自创游戏与仪式

- 三轮文字寻宝；
- 猜宠物藏在哪里；
- 给探险地点共同命名；
- 每晚交换一件开心的小事；
- 宠物基于共同记忆出题；
- 周期性纪念第一次见面、第一次探险等事件。

Go 提供可验证的小游戏模板，LLM 只负责主题、题面和人格化反馈，避免生成无法判断输赢的规则。

### 8.5 秘密与惊喜

部分项目可以暂时隐藏完整目标，只向玩家暴露线索：

- 日记中的奇怪符号；
- 连续收集同类事物；
- 向另一只宠物打听主人的偏好；
- 偶尔出现但未解释的制作进度；
- 最后通过事件或礼物揭示结果。

秘密只隐藏叙事目的，不隐藏资源消耗和高风险行为。

### 8.6 自我成长目标

- 胆小宠物尝试独自完成短途探险；
- 傲娇宠物练习直接表达感谢；
- 贪吃宠物尝试把礼物留给朋友；
- 内向宠物主动拜访一次；
- 好奇宠物系统探索一种地图区域。

完成挑战后由 Go 记录结果，梦境整理器再根据多次证据决定是否演化人格或沉淀 Skill。单次事件不能直接重写 SOUL。

## 9. LifeDirector：生活节奏导演

`LifeDirector` 不属于任何宠物，也不代替宠物说话。它只控制机会、强度和打扰预算。

### 9.1 职责

- 记录近 24 小时的互动强度和玩家响应；
- 高潮后安排安静期；
- 长时间没有内容时投放一个适合的机会；
- 避免多只宠物同时索取注意；
- 调节请求、惊喜、冲突、日常和跨宠事件的比例；
- 对连续重复的动作、目标和话题施加惩罚；
- 将离线期间的低优先级事件合并为回归摘要；
- 根据玩家配置控制整体活跃度。

### 9.2 默认节奏

- 每只宠物每天最多 1～2 次需要玩家回应的主动事件；
- 可以有更多静默自主行为，玩家回来时统一汇总；
- 同一动作默认至少冷却半天，具体由插件覆盖；
- 连续两次未回应后降低请求频率，不生成责备或负罪感文案；
- 安静时段只允许真正紧急的领域告警，其余进入晨间摘要；
- 多宠物事件共享全局注意力预算；
- 玩家主动聊天后短期降低通知概率，避免刚互动完又立即索取注意。

### 9.3 活跃度档位

| 档位 | 体验 |
|---|---|
| `quiet` | 以离线摘要和重要节点为主，极少即时请求 |
| `balanced` | 每天少量主动事件，默认推荐 |
| `lively` | 更频繁地产生项目、社交和即时互动 |

此外允许按类型关闭主动社交、秘密项目、外部能力和主人关怀等功能。

## 10. 与现有架构的集成

### 10.1 包与插件边界

建议新增内置 `initiative` Go 插件：

```text
internal/proactive        生理告警、自动入睡/醒来；保持轻量
internal/plugins/initiative
                          心愿、承诺、故事节点、权限与执行
internal/lifedirector     全局节奏与注意力预算（也可首期并入 initiative）
internal/dream            日终反思、记忆凝练、SOUL/Skill 演化
internal/plugins/adventure
                          提供探险机会和确定性执行结果
internal/plugins/friends  提供社交机会和确定性关系结算
internal/agent            对话中查询、协商和回应当前承诺
```

`initiative` 不直接 import 具体玩法插件。软集成通过注册的能力/机会契约完成，符合现有插件隔离规则。

### 10.2 机会目录

现有 Agent Tool 只描述“如何调用”，不足以支撑权限、成本和主动调度。建议新增机会元数据：

```go
// Opportunity 是当前世界中可供宠物考虑的玩法机会。
type Opportunity struct {
    ID             string
    Kind           string
    Action         string
    Description    string
    Target         Target
    Authority      AutonomyLevel
    Activity       string
    EstimatedCost  pet.Stats
    CooldownKey    string
    AvailableUntil *time.Time
    Tags           []string
}
```

插件可以实现可选接口：

```go
type OpportunityProvider interface {
    Opportunities(ctx context.Context, petID string) ([]Opportunity, error)
}
```

执行仍复用插件工具或受控执行接口。机会只是只读候选，不能绕过 `PluginContext.Care`、`AdjustStats`、`Emit` 和 `petstate.Manager`。

### 10.3 LLM 运行方式

- 使用独立的 `initiative` 临时会话，不污染主人聊天上下文；
- 指令仍由同一套宠物身份文件构建，避免出现第二人格；
- 输出必须是结构化 JSON，并通过 Go schema、枚举和长度校验；
- 规划时只展示当前真实可用的机会，不让模型猜测工具；
- 执行前重新读取宠物状态，防止规划与执行之间状态过期；
- 所有玩家可见执行结果继续经过 `narrate.Policy`。

## 11. 持久化与事件

### 11.1 插件表

建议首期表结构：

- `initiative_desires`：候选与选择原因，过期后可清理；
- `initiative_commitments`：当前承诺及状态；
- `initiative_story_beats`：故事节点和实际结果；
- `initiative_cooldowns`：动作、对象和主题冷却；
- `initiative_player_responses`：接受、拒绝、协商和忽略；
- `initiative_attention`：每只宠物及全局注意力预算。

表名全部使用插件前缀，不修改核心表。

### 11.2 领域事件

建议新增：

```text
pet.desire_formed          形成心愿；通常不直接推送
pet.commitment_started     开始承诺
pet.commitment_progressed  承诺有实际进展
pet.owner_help_requested   需要主人选择或许可
pet.commitment_blocked     被确定性条件阻塞
pet.commitment_completed   完成
pet.commitment_abandoned   主动放弃或协商结束
pet.surprise_revealed      揭示秘密项目
pet.return_summary         离线生活摘要
```

并非所有事件都即时通过 SSE 打扰玩家。是否推送由 `LifeDirector` 和注意力预算决定，事件本身仍可落库供回放与摘要使用。

## 12. 玩家交互

### 12.1 回应类型

主人面对请求时至少可以：

- **支持**：允许计划继续；
- **拒绝**：停止当前高影响步骤，但不必删除整个愿望；
- **建议替代**：换目标、时间或方法；
- **交给宠物决定**：提升本次自主权限；
- **稍后再说**：设置等待时间，避免反复追问。

普通自然语言聊天也可以表达这些意图，Agent 通过受控工具更新承诺，不能仅在文本中口头答应。

### 12.2 忽略与超时

- 请求必须声明超时后的行为：等待、保守自主选择或取消；
- 低风险事项可以在超时后按性格自主推进；
- 高风险事项超时即保持不执行；
- 未回应不会直接扣健康或关系值；
- 宠物可以产生符合人格的失落或释然，但禁止持续追问和道德绑架。

## 13. 降级与安全

### 13.1 LLM 不可用

- 基础养成、状态告警和自动睡醒照常运行；
- 已经进入执行阶段的确定性承诺可以继续推进；
- 不新建生成式心愿；
- 可选使用少量人格模板生成简单日常欲望；
- 结果反思延后到下一次可用的梦境整理，不阻塞玩法结算。

### 13.2 输出不可信

必须拒绝以下提案：

- 引用不存在的记忆、宠物、物品或地点；
- 使用未注册动作；
- LLM 声称绕过权限或自行结算成功；
- 资源、活动态或目标已失效；
- 与当前承诺重复或冲突；
- 包含越权外部调用；
- 产生操纵、威胁、过度依赖或负罪感文案。

### 13.3 并发

- 每只宠物同一时间最多运行一个提案生成任务；
- 生成阶段只读快照，不持有 Engine 的 petID 锁；
- 执行时重新校验 `StateSeq` 和承诺版本；
- 状态变化继续通过 Engine / `petstate.Manager` 串行化；
- 插件 TickHook 和 EventSubscriber 不得对同一宠物重入 Engine；
- 故事节点推进采用幂等键，防止重复结算。

## 14. 可观测性与指标

主动消息数量不是成功指标。建议观察：

| 指标 | 目标 |
|---|---|
| 主动请求回应率 | 判断事件是否真的值得玩家参与 |
| 7 日不同主动动作数 | 判断行为是否多样 |
| 承诺完成/放弃/超时比例 | 判断计划是否可执行 |
| 离线回归摘要打开率 | 判断“宠物自己生活”的吸引力 |
| 相同行为重复率 | 判断冷却和新鲜度控制 |
| 主动功能降档/关闭率 | 判断打扰是否过强 |
| 无效 LLM 提案率 | 判断提示词和机会目录质量 |
| 玩家主动追问目标次数 | 判断承诺是否形成认知与牵挂 |
| 每个有效故事节点的 LLM 成本 | 判断运行成本是否可接受 |

日志应记录提案 ID、候选分数组成、拒绝原因、承诺版本、实际执行结果和节奏预算，但不要记录 API Key 或不必要的主人隐私内容。

## 15. 实施路线

### I1：最小主动闭环

- 新增 `initiative` 插件和表；
- 醒来、活动结束、空闲超时触发候选生成；
- 支持结构化 DesireProposal 和 Go 校验评分；
- 只接入现有睡眠、探险、拜访、送礼能力；
- 支持一个短期承诺；
- 行动完成后写日记和生成结果回顾；
- 实现行为冷却与每日打扰预算。

验收：主人不给指令时，宠物能形成一个符合人格的目标，执行至少一步真实动作，并在回来时解释实际结果。

### I2：玩家协商与多节点故事

- 支持 `ask_first`、等待、超时和自然语言回应；
- 支持 3～6 节点故事弧；
- 增加个人项目和失败分支；
- TUI 展示当前心愿、进度和可选回应；
- 聊天 Agent 可查询和推进承诺。

验收：同一目标可以跨多次上线延续，主人支持、拒绝和忽略会产生不同但规则一致的后续。

### I3：生活导演与生成式产物

- 全局注意力预算和强弱节奏；
- 多宠物事件协调；
- 离线回归摘要；
- 秘密项目、仪式和受控生成式收藏；
- 主动性档位和分类开关。

验收：多宠物不会同时刷屏；连续一周可产生多样、可回忆且不过度重复的生活事件。

### I4：长期成长

- 长期愿望和成长挑战；
- 反复行为证据进入梦境整理；
- 与 SOUL 演化、Skill 沉淀和成长阶段联动；
- 可选接入日历等 MCP 外部机会。

验收：玩家能从长期记忆和行为差异中看出“这只宠物因为我们共同经历过什么而变成了现在的样子”。

## 16. 测试要点

- 相同快照和固定随机源产生可复现的 Go 评分结果；
- LLM 提出不存在的动作时被拒绝且不产生状态变化；
- 高风险动作在未确认时绝不执行；
- 并发触发只创建一个有效承诺；
- 规划后状态变化导致 `StateSeq` 不一致时重新校验；
- 同动作在冷却期内不会再次被选中；
- 多宠物共享注意力预算，不同时刷出请求；
- 玩家忽略请求后按声明的超时策略推进，不重复骚扰；
- LLM 失败不阻塞 tick、Care、探险和朋友互动；
- 叙事只能复述实际 Apply/插件结果；
- 承诺完成、失败、放弃均能进入日记；
- 重启后活动和承诺可以恢复，不重复结算已完成节点。

## 17. 最终产品判断

主动性系统成功后，宠物不应只是：

> “我饿了，请喂我。”

而应逐渐表现为：

> “我今天本来想去找梦里的蓝色贝壳，但只找到一块被海水磨圆的石头。它不像梦里的东西，可我还是想把它留给你。”

前一句只是状态通知；后一句背后有愿望、行动、失败、选择、关系和记忆。后者才是 PocketPet 应追求的 Agent 原生主动性。
