# 08 - 探险地图主题生成（LLM）

> 探险插件的地图分两层：**拓扑在 Go，主题在 LLM**。
> 拓扑（连通性、DAG、宝箱数量）是玩法规则，由 `GenerateMap` 确定性生成；
> 岛名、地点名、地点描述是叙事皮肤，由 LLM 生成，失败时降级到内置词库。
> 本文档是地图主题生成的规范与实现说明。

## 1. 分层架构

```
拓扑层   GenerateMap → MapGraph（DAG + 宝箱位置）        纯 Go，可测可控
主题层   Themer.ThemeIsland → IslandTheme                LLM 唯一调用点
降级层   FallbackThemer（内置词库）                       LLM 未配置/失败/超时时使用
```

- `Themer` 是注入 `Adventure` 的可选接口；nil 或返回错误时走 `FallbackThemer`。
- LLM 实现经 `adkx.Ephemeral` 一次性调用（无历史、无工具），要求 JSON 输出。
- 无论哪条路径，产出的 `IslandTheme` 必须通过同一份 Go 校验后才落库——**不信任 LLM 输出**。

## 2. 核心类型

```go
// ThemeRequest 是一次主题生成的输入（Go 侧从拓扑计算）。
type ThemeRequest struct {
    Seed       string    // 主题种子（词库随机抽取，保证多样性）
    NodeCount  int
    ChestNodes []int     // 宝箱节点编号，供描述暗示藏宝
    Edges      []MapEdge // 完整边列表，供安排地形过渡
    Zones      []string  // 每个节点所属地带（按下标对应，硬约束）
}

// IslandTheme 是一张地图的叙事皮肤。
type IslandTheme struct {
    IslandName string          // 岛名
    Theme      string          // 一句话岛屿主题
    Locations  []LocationTheme // 长度必须等于 NodeCount
}

type LocationTheme struct {
    ID          int      // 对应节点编号，必须恰好是 0..N-1 的排列
    Name        string
    Description string
    Zone        string   // 必须等于请求中下发的值
    Elements    []string // 描述覆盖的要素（见 §3 词表）
}
```

## 3. 要素（elements）词表

`elements` 是受控枚举，全部两字中文标签；LLM 输出与 Go 校验共用此表。

| 值 | 含义 | 示例短语 |
|---|---|---|
| `地貌` | 地形、地质构造 | 火山岩台地、环形珊瑚礁、海蚀洞 |
| `风景` | 可见景观 | 金色海崖、终年不散的雾、发光浮游生物 |
| `渊源` | 历史、传说、成因、命名由来 | 沉船水手的避难所、古时祭祀遗迹 |
| `环境` | 氛围与感官（声音、气味、体感） | 风带咸味、阴冷潮湿、蝉鸣不止 |
| `气候`（可选） | 天气与季节 | 午后雷阵雨、常年逆风 |
| `生物`（可选） | 特色动植物 | 蓝羽海鸟、发光苔藓 |
| `危险`（可选） | 潜在威胁 | 暗流、松动崖壁、瘴气 |

规则：

- 每地点 1–3 项；前四项为常规要素，至少命中其一。
- `危险` 只允许出现在深处带节点。
- 标注的要素必须在描述句中真实出现（写审一致）。

## 4. 地带分带（zone）

换图时 Go 从入口做 BFS 求每个节点深度，按深度划带，随请求下发：

| 地带 | 深度 | 允许的地形 |
|---|---|---|
| `海岸带` | depth ≤ 1 | 沙滩、礁石、浅湾、潮池、红树林 |
| `内陆带` | 1 < depth ≤ maxDepth/2 | 丛林、沼泽、溪谷、草原、丘陵 |
| `深处带` | depth > maxDepth/2 | 高地、火山口、遗迹、洞穴、深渊 |

LLM 输出的 `zone` 必须等于下发值——这是机器可校验的硬约束，
保证"海岸带不会出现雪山之巅"。

## 5. 相邻地点的地形连续性

相邻（有边相连）地点的地形过渡不能违背常识，分两级保证：

**机器侧（硬约束）**：地带单调。DAG 的边总是小编号 → 大编号，深度沿边不减，
所以跨带的边天然满足"海岸 → 内陆 → 深处"单向递进；Go 校验每条跨带边方向一致。

**Prompt 侧（软约束，失败重试一次）**：

- 同地带内相邻地貌须可直接过渡（沙滩 → 礁石滩）。
- 洞穴/溶洞只能在内陆带或深处带，且其前驱须是山体、岩壁类地形。
- 水域地形（湖、沼泽）的前驱须有水源（溪谷、河流、多雨环境）。
- 沿边海拔趋势不得骤降（不能丛林一步到火山口再回浅滩）。

## 6. 命名与描述规范

**岛名**：2–8 个汉字，"特征 + 通名"（岛/屿/礁/渚/沙洲/群岛），呼应主题种子；
不得用现实地名、人名、数字与现代词汇。`theme` 一句话 ≤30 字概括全岛基调。

**地点名**：2–6 字，全图唯一；命名呼应地带（海岸带：滩/湾/礁/桥；内陆带：林/泽/谷/径；
深处带：窟/巅/坛/渊）。节点 0 语义固定为登陆点。宝箱节点名可暗示藏宝，不强制。

**描述句**：一句话，15–40 字，句号结尾；客观旁白口吻（导游手册风格），不用人称代词，
不出现宠物名；写具体（"黑色玄武岩柱呈六边形排列"，而非"这里有奇特的地貌"）；
越深越神秘，危险用暗示不用血腥；人工物须以"遗迹/旧"形式出现。

## 7. 输出契约（JSON）

```json
{
  "island_name": "雾鸣岛",
  "theme": "被浓雾封锁的孤岛，雾中传来鲸歌般的低鸣。",
  "locations": [
    {
      "id": 0,
      "name": "碎浪滩",
      "description": "登陆点的黑色沙滩上铺满被潮水磨圆的火山石，风里带着硫磺气息。",
      "zone": "海岸带",
      "elements": ["地貌", "环境"]
    }
  ]
}
```

## 8. Go 校验清单（任一不过 → 附原因重试一次 → 降级）

1. JSON 可解析、字段齐全；`locations` 的 `id` 恰好是 `0..N-1` 的排列。
2. 岛名 2–8 字；地点名 2–6 字且全图唯一。
3. 描述 15–40 字、单句（无换行）。
4. `zone` 与下发值一致；`危险` 仅深处带。
5. `elements` 每项 ∈ 词表，1–3 项，至少一个常规要素。

## 9. 换图流程与异步主题

换图周期改为**墙钟**：`MapRefreshInterval`（默认 6 小时，YAML
`plugins.adventure.map_refresh_interval_seconds`），TickHook 比较
`now - currentMap.CreatedAt` 判到期，取代旧的 tick 计数（`MapRefreshTicks` 已移除）。

活跃地图唯一性：`adventure_kv.current_map_id` 单行指针保证至多一张活跃；
换图按"建新图 → 切指针 → 清旧图"顺序，崩溃中途只留孤儿行（下次换图清掉）；
TickHook 每次检查时发现当前图缺失/损坏会立即自愈重建——不依赖重启，
且与周期开关无关（`MapRefreshInterval <= 0` 只关周期换图，不关自愈）。

LLM 调用是秒级慢操作，不能阻塞 tick / 步进路径，因此换图分两阶段：

1. **同步段**（TickHook 内，持 stepMu）：生成拓扑 + 降级主题 → 落库 → 中断进行中的探险。
   地图立即可用，全程毫秒级。
2. **异步段**（goroutine，30s 超时）：`Themer` 生成 LLM 主题 → 校验 → 一个短事务
   `UPDATE` 岛名/地点名/描述。失败仅记日志，地图保持降级主题，不影响玩法。

`Init` 首次建图走同一路径，不阻塞启动。

## 10. 存储（schema v3）

- `adventure_maps` 加列：`island_name TEXT NOT NULL DEFAULT ''`、`theme TEXT NOT NULL DEFAULT ''`。
- `adventure_nodes` 加列：`description TEXT NOT NULL DEFAULT ''`、`zone TEXT NOT NULL DEFAULT ''`、
  `elements TEXT NOT NULL DEFAULT '[]'`（JSON 数组）。

## 11. 叙事联动

`adventure_status` 工具返回岛名与当前地点描述，移动/宝箱事件使用主题化地点名，
PetAgent 叙述探险时自然引用地貌风景。LLM 生成内容只进叙事，不回流影响数值。
