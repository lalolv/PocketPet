# PocketPet 架构设计方案

> 版本：v0.2（Agent 中心视角重写）
> 前置文档：`docs/01-调研报告.md`、`docs/02-技术选型评估.md`
> v0.2 修订说明：根据反馈将设计重心从"系统养宠物"翻转为"**宠物即 Agent**"——主人直接和宠物对话；每只宠物由一组人格文件定义；性格可随成长演化；睡眠时整理记忆，记忆可沉淀为技能。

## 0. 核心理念

```
一只宠物 = 一个 Agent = 一组文件 + 一个数值状态 + 一个运行时
```

- **宠物是主体**：主人直接和宠物对话，宠物以第一人称回应。不存在"系统助手"角色。
- **文件即存在**：宠物的人格、记忆、技能都是可读的文件——主人可以查看宠物"心里在想什么"，甚至可以备份、版本管理、迁移到另一台设备。
- **数值在 Go，灵魂在 LLM**（不变）：属性/成长/死亡规则确定性实现；人格、表达、记忆整理由 LLM 负责；LLM 不可用时核心养成照常运转。
- **经历塑造性格**：初始性格只是起点，成长阶段、相处模式、重要事件会让 SOUL.md 缓慢演化。
- **睡眠即整理**：睡觉不只恢复精力，还触发"梦境整理"——日记凝练成长期记忆，反复的经验沉淀为 Skill。

## 2. 宠物 = 一组文件

每只宠物一个目录（`data/pets/<pet-id>/`），**人格与记忆以文件为准（source of truth），数值状态存 SQLite**——叙事归文件，数字归数据库。

```
data/pets/<pet-id>/
├── PET.md            # 身份卡：名字、物种、生日、成长阶段、主人称呼、外貌描述
├── SOUL.md           # 灵魂：性格特质、说话风格、喜好与雷区（会随成长被改写）
├── INSTRUCTIONS.md   # 行为准则：回应规则与边界（模板初始化，相对稳定）
├── AGENT.md          # 装配声明：用哪个 model provider、启用哪些技能/工具/MCP
├── MEMORY.md         # 长期记忆：凝练后的事实与感悟（"主人叫阿洛，常熬夜"）
├── memory/           # 情景记忆：日记式原始记录
│   └── 2026-08-08.md
├── skills/           # 这只宠物学会/安装的技能（睡眠沉淀或外部放入）
│   └── goodnight-ritual/SKILL.md
└── avatar.md         # 外观/表情的文字描述（随成长阶段更新，供前端渲染参考）
```

### 各文件职责

| 文件 | 写入时机 | 演化频率 | 类比 |
|---|---|---|---|
| `PET.md` | 创建时；成长阶段变更时 | 极低 | 户口本 |
| `SOUL.md` | 创建时初始化；睡眠整理/重大事件时小幅改写 | 低（渐进） | 性格 |
| `INSTRUCTIONS.md` | 由系统模板生成，主人可微调 | 极低 | 家教 |
| `AGENT.md` | 主人通过 API/编辑修改 | 主人决定 | 装备栏 |
| `MEMORY.md` | 睡眠整理时合并写入 | 每次睡眠 | 长期记忆 |
| `memory/*.md` | 交互中由 `remember` 工具追加 | 高频 | 日记 |
| `skills/` | 睡眠沉淀自动产出，或主人放入 | 顿悟时刻 | 经验 |

### 指令装配（运行时）

Agent 的 system instruction 在每次运行时动态拼装：

```
INSTRUCTIONS.md（行为准则）
+ PET.md（我是谁）
+ SOUL.md（我的性格）
+ 当前状态快照（数值、心情、成长阶段）
+ MEMORY.md 摘要 + 近期日记摘要
+ 可用技能清单
```

原则：**数值快照只作为背景注入，宠物被明确要求"不直接报数值，用生命化的语言表达状态"**（饿不说"饱食度 35"，说"肚子咕咕叫"）。

## 3. 对话模型：主人 ↔ 宠物

### 3.1 第一人称交互

- 主人对宠物说"去睡觉吧"，**宠物自己决定**要不要睡：调用 `sleep` 工具作用于自己，然后回"好困……晚安，做个好梦"。
- 吃东西、玩耍、洗澡是主人专属的照顾动作（care 通道）：宠物只能表达需求（"肚子咕咕叫"）、等主人来做，不能自己动手——照顾循环是主人互动的核心。
- 宠物有自己的意愿：性格（SOUL.md）和状态共同影响决策——傲娇的猫可能拒绝，困极了会主动说"我想去睡了"然后真的去睡。
- 宠物答应要做的事必须真的调用对应工具执行，只说不做是不允许的。

### 3.2 两条交互通道，同一领域内核

| 通道 | 语义 | 路径 |
|---|---|---|
| `POST /pets/{id}/chat` | 主人对宠物**说话** | → PetAgent（LLM 决策，可能调用自我行为工具） |
| `POST /pets/{id}/care` | 主人对宠物**做事**（喂食、洗澡、抚摸） | → 领域层直接执行 → 产生事件 → Agent 生成感谢/反应（`pet.message`） |

两条通道最终都落在同一组领域方法上，数值行为永远一致。物理设备上的"喂食按钮"走 care 通道；对话框走 chat 通道。

## 4. 性格系统（SOUL）

### 4.1 初始性格

创建宠物时三选一：
- 主人选择预设模板（活泼 / 安静 / 傲娇 / 憨厚……）；
- 主人用一段自然语言描述，LLM 生成 SOUL.md；
- 完全随机（开盲盒）。

SOUL.md 采用 frontmatter（结构化特质权重，供确定性数值修饰使用）+ 正文（叙事化性格描述，供 LLM 表达使用）：

```markdown
---
traits:
  playfulness: 0.8   # 活泼度
  timidity: 0.2      # 胆小度
  appetite: 0.6
  sociability: 0.9
---
一只精力旺盛的小猫，话多，喜欢用反问句。害怕打雷。最喜欢主人摸下巴。
```

### 4.2 性格的两个作用面

- **表达面**：注入指令，决定说话风格（LLM 负责）。
- **数值面**：frontmatter 的特质权重作为**确定性修饰器**作用于领域层——如 `playfulness` 高则 play 的 Happy 增益 +20%，`appetite` 高则饥饿衰减略快。规则写在 Go 代码里，LLM 不参与计算。

### 4.3 性格演化

- **触发点（确定性）**：成长阶段变更；某种相处模式持续 N 天（如长期缺乏陪伴）；重大事件（生病痊愈、主人改名）。
- **演化方式**：由"反思流程"（见第 6 节）在睡眠中对 SOUL.md 做**小幅改写**，保留旧版本到 `SOUL.history/` 供回溯。
- **护栏**：单次改写幅度受约束（特质权重单步变化有上限）；主人可通过 API 查看变更、回滚或**锁定** SOUL.md 禁止演化。

## 5. 记忆系统

三层记忆，由近及远：

| 层 | 载体 | 生命周期 |
|---|---|---|
| 工作记忆 | ADK session（对话上下文） | 当前会话 |
| 情景记忆 | `memory/YYYY-MM-DD.md` 日记 | 永久保留，定期被压缩 |
| 长期记忆 | `MEMORY.md` | 永久，只在睡眠整理时更新 |

宠物拥有两个记忆工具：

- `remember(fact)` —— 交互中宠物**主动**把重要的事写进当天日记（"主人今天心情不好"）。何时记由宠物自己判断。
- `recall(query)` —— 对话中检索记忆（MEMORY.md + 近期日记），让"你还记得上周吗"类对话成立。

## 6. 睡眠与梦境整理（核心亮点）

`sleep` 是系统设计中最 Agent 化的环节。流程：

1. **入睡**（领域层，确定性）：进入睡眠状态，Energy 开始恢复，触发 `pet.fell_asleep` 事件。
2. **梦境整理**（LLM 异步任务，失败降级为跳过）：
   - **吸收**：读取近期日记与会话摘要；
   - **凝练**：提炼重要事实合并入 `MEMORY.md`（去重、更新矛盾条目）；
   - **反思**：长期相处模式触发 SOUL.md 小幅演化（见 4.3）；
   - **顿悟**：当某类经验反复出现（如主人每晚说晚安），**把它沉淀为一个 Skill**——生成 `skills/goodnight-ritual/SKILL.md`，经 skilltoolset 挂载后宠物就"学会了"这个技能；
   - **做梦**：生成一段梦境独白，作为 `pet.dream` SSE 事件推送（前端可以显示"宠物在睡梦中呢喃……"）。
3. **醒来**（确定性 + LLM 表达）：Energy 恢复完成或被唤醒，宠物根据"睡得如何 + 梦到了什么"生成醒来的第一句话。

设计要点：

- **触发是确定性的，内容是生成式的**——入睡/醒来/能量恢复由 Go 规则保证，整理质量不影响核心功能。
- **Skill 沉淀即经验固化**：这是"宠物越养越聪明"的机制载体，学到的技能文件主人可见、可删、可分享——未来甚至可以形成"宠物技能交换"生态。
- 沉淀的 Skill 遵循 ADK SKILL.md 规范，与手工编写的技能、第三方技能走同一加载路径，**无特例**。

## 7. 数值内核（不变，保持确定性）

属性（Hunger/Happy/Clean/Energy/Health/EXP）、tick 衰减、交互效果、成长阶段（egg→baby→child→adult）、健康/死亡、离线结算（带上限）——全部维持 v0.1 设计，纯 Go 实现，见 `internal/pet`。性格修饰器（4.2）是本层唯一新增点，同样是确定性规则。

成长阶段变更除了数值外，新增**成长仪式**：更新 PET.md（阶段、外貌描述）、触发 SOUL.md 演化窗口、生成成长感言事件 `pet.stage_up`。

## 8. Agent 运行时与扩展体系

### 8.1 PetAgent 运行时

- 每只宠物惰性创建一个 ADK `llmagent`，进程内缓存；配置来自该宠物的 `AGENT.md`（provider、模型、启用的技能与 MCP）。
- 工具清单：
  - **自我行为**：`sleep` `wake` `get_own_status`（包装领域层；feed/play/clean 为主人专属，走 care 通道）
  - **记忆**：`remember` `recall`
  - **技能**：`skills/`（宠物私有）+ 全局 `skills/`（经 skilltoolset 挂载）
  - **MCP**：`AGENT.md` 声明的外部 MCP servers
- 降级：LLM 不可用 → chat 返回预置性格化文案（按 SOUL 模板），care 动作与 tick 不受影响。
- **Provider 工厂（internal/llm）**：配置为 **YAML 配置文件 + 环境变量覆盖**（启动参数 `-config` > env > 文件 > 默认值；文件探测 `./pocketpet.yaml`、`./configs/pocketpet.yaml`，示例见 `configs/pocketpet.example.yaml`）。文件里 `llm.providers` 声明命名 provider（密钥经 `api_key_env` 间接引用环境变量），`llm.default` 选定全局默认；无命名 provider 时回退 env 单 provider 模式（`POCKETPET_LLM_PROVIDER/MODEL/BASE_URL/API_KEY`，完全向后兼容）。AGENT.md 可按宠物覆盖：provider 字段先按命名 provider 匹配，匹配不到按类型名回退；model 字段覆盖命名 provider 的 model。provider 类型：
  - `gemini`：Google Gemini（`GOOGLE_API_KEY` / `GEMINI_API_KEY`）。
  - `openai-compatible`：**Responses API**（`/v1/responses`）——OpenAI 官方、新 vLLM/Ollama；回退 `OPENAI_API_KEY` / `OPENAI_BASE_URL`。
  - `openai-chat`：**Chat Completions 兜底适配**（`/v1/chat/completions`，已实现于 `internal/llm/chatmodel`）——DeepSeek/Moonshot/通义/老端点。该 provider 必须显式给模型名（不猜默认）。env 示例：`POCKETPET_LLM_PROVIDER=openai-chat POCKETPET_LLM_BASE_URL=https://api.deepseek.com/v1 POCKETPET_LLM_MODEL=deepseek-chat`。

### 8.2 三层扩展体系

1. **SKILL.md 技能包**（运行时加载，默认首选）：扩展宠物的"行为能力与叙事"，全局或宠物私有——**包括睡眠沉淀产出的技能**。只能影响表达和 LLM 行为，天然是安全的沙箱层。
2. **MCP**（进程外 / 远程）：能力在系统边界之外（查天气、智能家居、物理喂食器舵机），可用任意语言实现。
3. **Go 插件**（编译期，内核级扩展）：触及确定性内核的扩展——新事件、新数值规则、新成长线、新存储。

分工铁律：**规则进插件，叙事进 Skill，外部进 MCP**。掉落表、好感度这类数值逻辑绝不写成 SKILL.md 让 LLM"编"，否则破坏"数值在 Go"原则。

### 8.3 插件能力接口集

插件不是单一胖接口，而是**核心接口 + 可选能力接口集**，按需实现、装配时类型断言发现：

```go
// 核心接口：所有插件必须实现
type Plugin interface {
    Name() string
    Init(ctx PluginContext) error // PluginContext 提供宠物目录（跨宠物访问）、配置、日志
}

// 可选能力接口：
type ToolProvider    interface { Tools() []tool.Tool }           // 向 PetAgent 注册新工具
type EventSubscriber interface { OnEvent(ctx context.Context, e pet.Event) } // 领域事件钩子
type TickHook        interface { OnTick(ctx context.Context, now time.Time) } // tick 结算
type RouteProvider   interface { Routes() []api.Route }          // 注册新 REST 路由
type SchemaProvider  interface { Migrations() []store.Migration } // 新增 SQLite 表/迁移
```

能力覆盖回测（后续玩法的插件化评估）：

- **探险**（消耗精力 → 随机事件 → EXP/物品奖励）= `ToolProvider`（`adventure_start`/`adventure_claim`，宠物可说"我要去探险！"并真的执行）+ `TickHook`（耗时结算）+ `SchemaProvider`（物品背包表）+ `RouteProvider`（背包/日志查询 API）+ 一个教宠物讲述探险经历的 SKILL.md → **可完整实现，不动主程序**。
- **交友·同实例**（一台设备多只宠物）= `ToolProvider`（`visit_friend`/`gift`）+ `SchemaProvider`（好感度表）+ 跨宠物访问（`PluginContext` 的宠物目录）；两只宠物对话用 ADK `agenttool` 编排 → **可实现**。
- **交友·跨实例**（不同设备的宠物互动）= 不属于插件问题，走 **A2A 协议**（`server/adka2a` 暴露宠物为 A2A Agent，远程宠物以 `remoteagent` 接入），插件仅作为发起方调用远程接口。

### 8.4 插件信任边界

- 插件能注册 Schema、改数值，等同内核权限，**只接受可信来源、编译期引入**，不支持第三方二进制热插拔。
- SKILL.md 与 MCP 是低权限层：不能改数值，只能影响表达、调用已暴露的工具——适合开放给社区与宠物自沉淀。
- 插件间的加载顺序与依赖暂不引入包管理器式机制；有依赖时在 `Init` 中显式检查并报错。

## 9. API 设计（v0.2 更新）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/v1/pets` | 创建宠物（名字、物种、性格模板或自然语言描述、provider 覆盖） |
| GET | `/v1/pets` / `/v1/pets/{id}` | 列表 / 状态查询（Stats、Stage、Mood） |
| POST | `/v1/pets/{id}/chat` | **和宠物对话**；`?stream=true` SSE 流式 |
| POST | `/v1/pets/{id}/care` | 照顾动作 `{ "action": "feed" }`（对宠物做事） |
| GET | `/v1/pets/{id}/events` | SSE 事件流（message/dream/skill_learned/soul_changed/stage_up…） |
| GET | `/v1/pets/{id}/soul` | 查看 SOUL.md（含演化历史列表）；POST `.../soul/lock` 锁定 |
| GET | `/v1/pets/{id}/memory` | 查看 MEMORY.md / 日记 |
| GET | `/v1/pets/{id}/skills` | 该宠物的技能列表（含学到的） |
| GET | `/v1/meta/providers`、`/healthz` | 元信息 / 健康检查 |

**透明化是设计特性**：主人可以阅读宠物的灵魂、记忆和梦境——既是情感连接点，也是调试手段。

## 10. 持久化分工

| 数据 | 存储 | 理由 |
|---|---|---|
| 数值状态（Stats/EXP/阶段/时间戳） | SQLite（`internal/store`，modernc 纯 Go 驱动） | 高频事务更新，tick 友好 |
| 人格 / 记忆 / 技能 / 梦境记录 | 文件（`data/pets/<id>/`） | LLM 读写友好；主人可查看/备份/版本管理；Skill 加载路径天然兼容 |
| 领域事件流水 | SQLite `pet_events` 表 | 断线重放、审计 |

## 11. 项目结构（v0.2）

```
PocketPet/
├── cmd/pocketpetd/main.go
├── internal/
│   ├── config/        # 配置加载
│   ├── pet/           # 领域层：Stats/规则/事件/性格修饰器（不依赖 ADK、HTTP）
│   ├── store/         # SQLite：数值状态 + 事件流水

│   ├── tick/          # tick 引擎：衰减、离线结算、事件
│   ├── llm/           # model.LLM provider 工厂；llm/chatmodel/ 为 Chat Completions 兜底适配（已实现）
│   ├── agent/         # PetAgent：指令装配、工具包装、运行时缓存、降级文案

│   └── api/           # REST + SSE
├── skills/            # 全局技能包

├── configs/pocketpet.example.yaml  # 配置示例（YAML；真实 pocketpet.yaml 在 .gitignore）
├── docs/
```

## 12. 开发路线图（v0.2）

| 里程碑 | 内容 | 验收 |
|---|---|---|
| **M1 数值内核** | 领域层 + SQLite + tick + care/chat 占位 API（无 LLM） | 无 LLM 完整跑通养成闭环 |
| **M2 宠物 Agent** | petfs 文件体系 + PetAgent（对话、自我行为工具、remember/recall）+ provider 工厂 | 和宠物第一人称对话；断 key 降级正常 |
| **M3 记忆与梦境** | 睡眠整理流程：MEMORY.md 凝练、SOUL 演化（带护栏与回滚）、梦境事件 | 睡一觉后 MEMORY.md 更新、产出 pet.dream |
| **M4 技能沉淀与生态** | 经验沉淀为 Skill + 全局 skills 加载 + MCP + A2A + ARM 交叉编译验证 | 反复经验自动生成 SKILL.md 并生效 |
| **M5 插件体系验证** | 落地插件能力接口集（8.3），以"探险"插件 + 同实例"交友"插件做验证；跨实例交友走 A2A | 两个玩法不改主程序、纯插件实现 |

## 13. 非功能性设计

- **并发**：每只宠物的状态操作经 petID 锁串行化；梦境整理为异步任务，与对话并发安全（文件写入走 petfs 的统一锁）。
- **可测试**：领域层注入假时钟表驱动测试；Agent/梦境流程用 ADK mock model；petfs 用临时目录。
- **可观测**：`slog` 结构化日志；SOUL/SKILL 的每次自动改写记录事件流水，可审计。
- **嵌入式**：纯 Go 无 cgo；文件 + SQLite 双存储均为本地小文件，资源占用低。
