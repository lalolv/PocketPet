# 探险插件设计（地图图结构）

> 版本：v0.1  
> 前置文档：`docs/03-架构设计方案.md` §8、`docs/05-插件开发指南.md`  
> 状态：**落地中**（A0–A4）；与 friends 等玩法插件彼此独立  
> 实现包：`internal/plugins/adventure`

## 0. 动机与目标

现行探险是线性倒计时：`adventure_start` 扣精力 → `TickHook` 倒数 3 tick → 随机掉落进 `adventure_items`。玩法扁平，无法表达「地点 / 道路 / 分支抉择」。

**目标**：把探险改成**系统周期性生成一张共享地图**，地图是**有向图**（节点=地点，边=道路）；宠物进入后沿分支前进，路过宝箱时**只展示信息**（本阶段不落背包、不加数值）。

**非目标（本版不做）**：

- 宝箱开出真实物品 / 写入背包 / 改 Stats；
- 复杂地形权重、战斗、解谜、多张并行地图；
- LLM 生成地图拓扑（拓扑必须确定性，规则在 Go）。

## 1. 需求摘要

| # | 需求 | 本版落地 |
|---|---|---|
| 1 | 每隔一段时间系统生成一张探险地图 | `TickHook` 计数，达阈值则重生当前地图 |
| 2 | 地图为图结构：节点 + 边，节点可多分支 | `MapGraph{Nodes, Edges}`，出边数 ≤ `MaxBranches` |
| 3 | 最简生成：分支上限（默认 5）；生成时随机放奖励 | 生成树 + 额外前向边；奖励=宝箱标记 |
| 4 | 奖励暂用宝箱；数量 = 节点数的 m%–n% 取整 | **m=15，n=25**（见 §3.3） |
| 5 | 到达节点后随机选分支继续；获奖励只显示信息 | 每 tick 前进一步；宝箱 → 事件文案，无其它逻辑 |

完全重构现行插件逻辑。**玩法插件彼此独立**：探险不向其它插件暴露背包 API，也不依赖 friends。

---

## 2. 与插件框架的适配评估

对照 [`docs/05-插件开发指南.md`](05-插件开发指南.md)：

| 能力 | 是否够用 | 用法 |
|---|---|---|
| `SchemaProvider` | ✅ | 地图 / 节点 / 边 / 行程 / kv 表 |
| `TickHook` | ✅ | 地图刷新计时 + 行程每 tick 前进一步 |
| `ToolProvider` | ✅ | `adventure_start` / `adventure_status` |
| `RouteProvider` | ✅ | 查当前地图、宠物行程 |
| `PluginContext` | ✅ | `GetPet` / `AdjustStats`（仅出发扣精力）/ `Emit` / `DB` |
| `EventSubscriber` | 本插件不需要 | — |
| 改 `pet`/`tick`/`store` 领域层 | ❌ 不需要 | 符合「规则进插件」 |
| 依赖其它玩法插件 | ❌ 不需要 | 彼此独立 |

**结论：指南可以完整支撑本需求，无需扩展插件契约，也无需与 friends 耦合。**

边界说明：

- 「每隔一段时间换图」用 **墙钟周期**（`map_refresh_interval_seconds`，默认 6 小时）；「行程步进」用独立墙钟 `step_interval_seconds`（默认 5s），避免默认 60s tick 导致一步一分钟。
- 换图分两段：拓扑生成 + 降级主题落库是 CPU 轻量工作，须在 `OnTick` 内同步完成并保持 &lt;100ms；岛名/地点名/描述的 LLM 主题由 goroutine 异步生成后就地更新（规范见 `docs/08-探险地图主题生成.md`）。
- 叙事（怎么讲探险见闻）仍可另加 SKILL.md；**拓扑与宝箱放置禁止进 Skill**。
- 领域事件（如 `pet.adventure_finished`）仅供展示 / SSE；**其它插件不应订阅并据此改自己的数值**（避免隐式耦合）。

## 3. 地图模型

### 3.1 结构

```text
MapGraph
  Nodes[]  { id, name, has_chest }
  Edges[]  { from, to }          // 有向边 = 道路
  Start    = 节点 0（「入口」）
```

约束（最简方案）：

- **有向无环（DAG）**：生成树 + 只允许连向更大编号的补边，避免环路导致行程永不结束。
- **出边上限** `MaxBranches`（默认 **5**）：每个节点最多 5 条出路。
- 出边为 0 的节点视为**终点**（行程结束）。

### 3.2 生成算法（最简）

1. 创建 `NodeCount` 个节点（默认 12）；`id=0` 名为「入口」。
2. **生成树**：对 `i=1..N-1`，从 `[0,i)` 中仍有出边配额的节点里随机选父节点，连边 `parent → i`（保证从入口可达）。
3. **补分支**：对每个节点，在出边未满且随机通过时，向更大编号节点再连边（去重、遵守上限）。
4. **放置宝箱**：按 §3.3 计算数量，在非入口节点中无放回抽样，置 `has_chest=true`。

可注入 `IntN` / `Float64` 便于单测确定性。

### 3.3 宝箱数量（m%–n%）

参考 Roguelike / 探索关卡常见「有宝箱的房间占比」约 **15%–25%**：

| 符号 | 值 | 含义 |
|---|---|---|
| m | 15% | 下限占比 |
| n | 25% | 上限占比 |

计算：

```text
minC = max(1, round(N * 0.15))
maxC = clamp(round(N * 0.25), minC, N-1)   // 入口不放宝箱，故上限 ≤ N-1
chestCount ∈ [minC, maxC] 均匀随机取整
```

示例：`N=12` → round(1.8)=2 … round(3.0)=3 → **2–3 个宝箱**；`N=20` → **3–5 个**。

本阶段宝箱=布尔标记；拾取只 `Emit` / 工具文案，**不** `AddItem`、**不** `AdjustStats`。

## 4. 运行时流程

```text
Init
  └─ 若无当前地图 → GenerateMap 并落库

OnTick（养成 tick）
  └─ now - 当前图 created_at ≥ 换图周期 → 换图（拓扑+降级主题同步落库）并中断旧行程；
     LLM 主题异步生成后就地 UPDATE

步进循环（墙钟 StepInterval，默认 5s）
  └─ 对每个进行中行程：advanceOneStep
        ├─ 当前节点若有未拾取宝箱 → 标记已见 + Emit「发现宝箱」（仅信息）
        ├─ 列出出边；若无 → 结束行程 + Emit pet.adventure_finished
        └─ 否则随机选一条边，Emit pet.adventure_moved，写入新当前位置

adventure_start（工具）
  ├─ View：Idle、精力 ≥ AlertWarn、够 energy_cost、无行程、有地图
  ├─ Apply(To=adventuring, StatsDelta=-Energy)（已占用 → ErrBusy/ErrAlready）
  ├─ 释放 petID 锁后于 stepMu 内 insertRun（锁序：只允许 stepMu → petID 锁，
  │     禁止反向嵌套，否则与步进/换图 AB-BA 死锁；登记失败补偿 Apply 回 idle，
  │     残留行程由步进自愈清理，精力不退还）
  └─ Emit pet.adventure_started

步进 advanceOneStep
  └─ 按节点/边推进；正常结束或换图中止时 Apply(To=idle)（可消费 IntentSleep → 自动睡）

adventure_status（工具）
  └─ 返回是否在途、当前地点名、剩余分支数、已发现宝箱数等纯展示文案
```

### 4.1 与活动态互斥

探险经 `petstate.Manager.Apply` 进入/离开 `adventuring`（见 [`07`](07-宠物状态管理器.md)）。忙时 AutoSleep 入队 IntentSleep，行程结束后自动入睡。

探险是持续**活动态** `adventuring`，与 `sleeping` 互斥（见 [`03`](03-架构设计方案.md) §7.1）：

- 睡觉中 / sleepy(Idle) 不可 `adventure_start`。
- 探险中 `Care(sleep)` / AutoSleep → 排队 `IntentSleep`（Queued/`ErrBusy`），不抢占行程。
- 占用真相在 `Pet.Activity`；`adventure_runs` 只存行程细节。
- Init：`RestoreActivity`；有 run 无 Activity / 有 Activity 无 run → 自愈。


默认节奏建议：

| 参数 | 默认 | 说明 |
|---|---|---|
| `map_refresh_interval_seconds` | 21600 | 自动换图墙钟秒数（默认 6 小时）；<=0 关闭 |
| `node_count` | 12 | 最简体量 |
| `max_branches` | 5 | 需求给定上限 |
| `energy_cost` | 15 | 仅出发时扣除；途中不再扣 |
| `step_interval_seconds` | **5** | 行程步进墙钟间隔（与养成 tick 解耦；12 节点图大约一分钟内走完） |

## 5. 存储（SchemaProvider）

迁移在旧版 `adventure_active` / `adventure_items` 之上追加版本（示例）：

```sql
-- 元信息：当前地图
CREATE TABLE adventure_kv (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL
);

CREATE TABLE adventure_maps (
  id         TEXT PRIMARY KEY,
  created_at TEXT NOT NULL,
  node_count INTEGER NOT NULL
);

CREATE TABLE adventure_nodes (
  map_id    TEXT NOT NULL,
  node_id   INTEGER NOT NULL,
  name      TEXT NOT NULL,
  has_chest INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (map_id, node_id)
);

CREATE TABLE adventure_edges (
  map_id TEXT NOT NULL,
  "from" INTEGER NOT NULL,
  "to"   INTEGER NOT NULL,
  PRIMARY KEY (map_id, "from", "to")
);

CREATE TABLE adventure_runs (
  pet_id          TEXT PRIMARY KEY,
  map_id          TEXT NOT NULL,
  node_id         INTEGER NOT NULL,
  chests_found    TEXT NOT NULL DEFAULT '[]', -- JSON int 数组
  started_at      TEXT NOT NULL
);
```

`adventure_items` / 背包 API：**删除**。本版无跨插件掉落共享；宝箱只展示信息。

旧表 `adventure_active`：迁移中 `DROP`，由 `adventure_runs` 替代。

## 6. 对外接口

### 6.1 工具（ToolProvider）

| 工具 | 行为 |
|---|---|
| `adventure_start` | 进入当前地图入口；失败用 `OK: false` + 文案 |
| `adventure_status` | 描述当前位置 / 是否在途 / 地图是否存在 |

### 6.2 HTTP（RouteProvider）

挂载前缀：`/v1/plugins/adventure/`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/maps/current` | 当前地图节点、边、宝箱标记 |
| GET | `/pets/{id}/run` | 该宠行程（若无则 `adventuring: false`） |
| POST | `/pets/{id}/start` | TUI/客户端直接出发（不经 LLM）；失败返回业务错误码 |

### 6.3 事件

| Type | 何时 |
|---|---|
| `pet.adventure_started` | 出发 |
| `pet.adventure_moved` | 每 tick 走到下一节点 |
| `pet.adventure_chest` | 首次踩到某宝箱节点（仅信息） |
| `pet.adventure_finished` | 走到死路 / 行程正常结束 |
| `pet.adventure_aborted` | 换图时强制中断进行中行程 |

事件仅供本玩法展示与 SSE；**不作为其它插件的契约**。

## 7. 独立性（相对其它玩法插件）

| 原则 | 做法 |
|---|---|
| 不 import friends 等玩法包 | 编译期无边 |
| 不维护「给别人用」的背包 API | 无 `TakeItem`/`AddItem` |
| 不要求对方订阅本插件事件 | finished/chest 只服务探险自身与客户端 |
| friends 送礼 | 交友插件内叙事送礼，与探险无关 |

## 8. 配置（YAML）

```yaml
plugins:
  adventure:
    enabled: true
    map_refresh_interval_seconds: 21600
    node_count: 12
    max_branches: 5
    chest_min_pct: 0.15   # m
    chest_max_pct: 0.25   # n
    energy_cost: 15
    step_interval_seconds: 5
```

装配仍走 `internal/plugins.Build` → `applyAdventure`；`cmd/pocketpetd` 不用改。

按职责拆分，避免单文件膨胀：

```text
internal/plugins/adventure/

  adventure_test.go
```

## 11. 与旧玩法对照

| | 旧版 | 新版 |
|---|---|---|
| 进度模型 | `ticks_left` 倒数 | 图上 `node_id` 步进 |
| 随机性 | 结束时掉落表 | 地图生成 + 每节点选出边 |
| 奖励 | 物品入背包 + EXP/Happy/受伤 | 宝箱信息展示 only |
| 地图 | 无 | 系统共享一张，定期刷新 |
| 跨插件 | friends 借背包 / 订 finished | **无耦合** |
| 插件接口 | 同四件套 | 同四件套（证明框架仍够用） |

## 12. 开放问题（可后续拍板）

1. 换图时进行中行程：强制 `aborted` vs 允许跑完旧图只读快照？**建议：强制中断**（实现简单）。
2. 多宠是否共享同一张当前图？**建议是**（「系统生成一张」）。
3. 宝箱是否允许重复踩踏多次播报？**建议每行程每节点只播一次**（`chests_found`）。
4. 若未来要「探险掉落可送礼」：在**单一插件内**闭环，或引入独立物品域——仍避免 adventure↔friends 双向依赖。
