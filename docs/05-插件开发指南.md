# 插件开发指南

面向要加新玩法的开发者与 vibe coding：按步骤落地一个 **Go 插件**。设计背景见 [`03-架构设计方案.md`](03-架构设计方案.md) §8。

参考实现：`internal/plugins/adventure`（工具 + Tick + 表 + 路由）、`internal/plugins/friends`（跨宠 + 软依赖 + 事件订阅）。

> 探险玩法正重构为「图结构地图」：见 [`docs/06-探险插件设计.md`](06-探险插件设计.md)。指南中的能力接口集仍足够实现该设计，无需改契约。

---

## 0. 先选层（30 秒）

| 你要改的是… | 放哪 |
|---|---|
| 掉落、扣精力、好感度、倒计时结算等**确定性规则** | **Go 插件**（本文） |
| 说话方式、仪式流程、教宠物怎么用工具 | **SKILL.md**（`skills/` 或宠物私有 skills） |
| 天气、家居、硬件等**进程外**能力 | **MCP**（配置 + `AGENT.md`） |

铁律：**规则进插件，叙事进 Skill，外部进 MCP**。不要把掉落表/好感写进 Skill 让 LLM「编」。

信任边界：Go 插件是**编译期、可信代码**，无第三方 `.so` 热插拔；改完需重编译 `pocketpetd`。

**注册方式（当前）：** 不是扫描目录自动发现。新建包后必须在 `internal/plugins/builtins.go` 的 `Build` 里显式 `New()` 并 `append`（可选再加 YAML 开关）。`cmd/pocketpetd` 已固定为 `NewRegistry(plugins.Build(cfg)...)`，一般不用改 main。

## 1. 新建包

```text
internal/plugins/<name>/
  <name>.go
  <name>_test.go   # 建议有
```

`Name()` 返回短名（如 `"training"`），须稳定：迁移版本键是 `plugin:<name>`，HTTP 前缀是 `/v1/plugins/<name>/`。

## 2. 实现核心接口 + 按需能力

**必须：**

```go
type Plugin interface {
    Name() string
    Init(ctx plugin.PluginContext) error
}
```

**按需实现（Registry 类型断言发现）：**

| 接口 | 方法 | 用途 |
|---|---|---|
| `ToolProvider` | `Tools() []adktool.Tool` | 给每只宠物 Agent 加工具 |
| `SchemaProvider` | `Migrations() []store.Migration` | 自己的 SQLite 表/迁移 |
| `TickHook` | `OnTick(ctx, now)` | 每轮 tick 结算后回调 |
| `RouteProvider` | `Routes() []plugin.Route` | REST，挂在 `/v1/plugins/<name>/...` |
| `EventSubscriber` | `OnEvent(ctx, e pet.Event)` | 订阅领域事件 |
| `Depender` | `DependsOn() []string` | **硬**依赖；缺失则启动失败 |
| `Shutdowner` | `Shutdown(ctx) error` | 进程退出清理（可选） |

软依赖不要用 `Depender`：在 `Init` 里 `pctx.HasPlugin("other")`，缺失则降级。  
**优先原则：玩法插件彼此独立**——不要为送礼/掉落去 import 另一个插件；各自维护自己的表与规则（见 [`06-探险插件设计.md`](06-探险插件设计.md)）。

## 3. `PluginContext` 完整能力面

`Init` 收到的是 `plugin.PluginContext`（下文记 `pctx`）。工具/钩子里的 `context.Context` 另记为 `ctx`，**不要同名混用**。

| 方法 | 说明 |
|---|---|
| `Logger() *slog.Logger` | 已带 `plugin=<name>` |
| `PluginName() string` | 当前插件名（Init 期内） |
| `HasPlugin(name) bool` | 软依赖：对方是否已注册 |
| `ListPets(ctx) ([]*pet.Pet, error)` | 列出全部宠物（**不**做离线补算） |
| `GetPet(ctx, id) (*pet.Pet, error)` | 读一只宠物（先 Settle/补算） |
| `FindPetByName(ctx, name) (*pet.Pet, error)` | 同实例按名查找；没有则 `store.ErrNotFound` |
| `Care(ctx, id, action) (*pet.Pet, error)` | 照顾动作（与 REST care 同路径）；sleep 时若有玩法占用则 `ErrBusy` |
| `AdjustStats(ctx, id, delta) (*pet.Pet, error)` | 确定性加减数值（负值=扣）；走钳制/晋升/告警 |
| `Activity(ctx, id) (string, error)` | 统一活动态：`idle` / `sleeping` / `adventuring` /… |
| `View(ctx, id) (Snapshot, error)` | Settle + 原子快照（含 Activity/Intents） |
| `Apply(ctx, id, Transition) (Result, error)` | **唯一**活动切换入口（含 StatsDelta/OnCommit/意图排队） |
| `RegisterActivity(ActivityKind)` | Init 注册玩法 Kind（CanEnter/AfterLeave） |
| `RestoreActivity(ctx, id, kind, owner)` | 重启对齐占用（跳过 CanEnter） |
| `Emit(ctx, ...pet.Event)` | 落库 `pet_events` 并 SSE |
| `ReadFile(id, name) (string, error)` | 读 petfs 顶层白名单文件（PET/SOUL/…） |
| `AppendJournal(id, text, now) error` | 追加当天日记（对方 `recall` 可达） |
| `DB() *sql.DB` | 共享 SQLite；见下方约定 |

包级辅助：

| API | 说明 |
|---|---|
| `plugin.PetIDOf(actx)` | 从工具 `adkagent.Context` 解析当前宠 ID（agent 名 `pet_<id>`） |
| `plugin.ToolResult` | `{OK, Outcome}`；业务拒绝用 `OK: false` |
| `plugin.Route` | `{Method, Pattern, Handler}`；Pattern 相对插件命名空间 |
| `plugin.CoreTables` | 禁止经 `DB()` 改写的核心表名列表 |
| `plugin.SlowTickWarn` | TickHook 慢告警阈值（100ms） |

### 改数值 / 发事件 / 写日记

```go
pctx.AdjustStats(ctx, petID, pet.Stats{Energy: -10, Happy: 5})
pctx.Care(ctx, petID, pet.ActionSleep)
pctx.Emit(ctx, pet.Event{PetID: petID, Type: "pet.my_event", Message: "...", CreatedAt: time.Now()})
pctx.AppendJournal(petID, "发生了某事。", time.Now())
```

### 持续活动必须走 petstate.Apply

瞬时工具（训练一次、送礼）用 `View`/`GetPet` 看 Activity 是否 idle。若玩法是**持续活动**，必须：

1. `RegisterActivity(ActivityKind{Name, Owner, CanEnter, AfterLeave})`；
2. 开始：`Apply(To: kind, Owner, StatsDelta, OnCommit=写私有表)`——同锁原子，禁止先 GetPet 再 Begin；
3. 结束：`Apply(To: idle)`（会消费 IntentSleep 等排队意图）；
4. Init：`RestoreActivity` 对齐 DB，与私有 run 不一致则自愈。

权威说明：[`07-宠物状态管理器.md`](07-宠物状态管理器.md)。

### 建表

实现 `Migrations() []store.Migration`。表名建议带插件前缀（如 `training_runs`）。版本在 `kv_meta` 的 `plugin:<name>`，与核心隔离。

### HTTP

```go
func (p *P) Routes() []plugin.Route {
    return []plugin.Route{{
        Method: http.MethodGet, Pattern: "/pets/{id}/stats", Handler: p.handle,
    }}
}
```

响应用 `internal/httpx`，**不要** import `internal/api`。完整路径：`GET /v1/plugins/<name>/pets/{id}/stats`。

### TickHook / EventSubscriber（易踩坑）

- **必须快返回**（建议 &lt;100ms）；超过会 Warn。重活自行 `go` 或分批。
- `OnEvent`：**不要**对同一宠物重入 `AdjustStats`/`Care`（`emit` 可能持有 pet 锁 → 死锁）。优先只做本插件表写入 / `AppendJournal`。
- 跨插件数据：默认**不要**耦合。若确需协作，走对方导出包级 API，不要直接 SQL 他插件的表；更推荐事件仅作展示、数值各算各的。

### DB()

共享 SQLite，信任约定：

- 只读写**本插件**表；
- 禁止改写核心表：`pets` / `pet_events` / `kv_meta`；
- 跨插件用包级 API，不要裸 SQL 耦合。

## 4. 注册与配置

### 4.1 `internal/plugins/builtins.go` 的 `Build`（必做）

新建插件**不会**被自动扫到。你需要：

1. `New()` 构造实例；
2. 用 YAML 覆盖数值（仿 `applyAdventure`）；
3. `cfg.<Name>Enabled()` 为 true 时 `append` 进返回切片（**顺序 = 装配顺序**，被依赖方靠前）。

### 4.2 配置（如需开关/调参）

在 `internal/config/config.go`：

1. 增加 `XxxPluginConfig`（`enabled *bool` + 可选数值指针）；
2. 挂到 `PluginsConfig`；
3. 增加 `XxxEnabled() bool`（`nil` = 默认启用）。

示例 YAML（见 `configs/pocketpet.example.yaml`）：

```yaml
plugins:
  training:
    enabled: true
    # energy_cost: 10
```

`cmd/pocketpetd` **不用改**：它只调用 `plugin.NewRegistry(plugins.Build(cfg)...)`。

## 5. 最小骨架（可复制）

```go
package training

import (
    "context"

    adkagent "google.golang.org/adk/v2/agent"
    adktool "google.golang.org/adk/v2/tool"
    "google.golang.org/adk/v2/tool/functiontool"

    "github.com/lalolv/PocketPet/internal/pet"
    "github.com/lalolv/PocketPet/internal/plugin"
    "github.com/lalolv/PocketPet/internal/store"
)

type Training struct {
    EnergyCost float64
    pctx       plugin.PluginContext
    tools      []adktool.Tool
}

func New() *Training { return &Training{EnergyCost: 10} }

func (t *Training) Name() string { return "training" }

func (t *Training) Migrations() []store.Migration {
    return []store.Migration{`CREATE TABLE training_logs (
        pet_id TEXT NOT NULL, at TEXT NOT NULL
    );`}
}

func (t *Training) Init(pctx plugin.PluginContext) error {
    t.pctx = pctx
    tool, err := functiontool.New(functiontool.Config{
        Name:        "train",
        Description: "做一次训练，消耗精力，心情变好。",
    }, func(actx adkagent.Context, _ struct{}) (plugin.ToolResult, error) {
        return t.train(actx, plugin.PetIDOf(actx))
    })
    if err != nil {
        return err
    }
    t.tools = []adktool.Tool{tool}
    return nil
}

func (t *Training) Tools() []adktool.Tool { return t.tools }

func (t *Training) Shutdown(context.Context) error { return nil }

func (t *Training) train(ctx context.Context, petID string) (plugin.ToolResult, error) {
    p, err := t.pctx.GetPet(ctx, petID)
    if err != nil {
        return plugin.ToolResult{}, err
    }
    if p.Sleeping {
        return plugin.ToolResult{OK: false, Outcome: "我在睡觉，没法训练"}, nil
    }
    if p.Stats.Energy < t.EnergyCost {
        return plugin.ToolResult{OK: false, Outcome: "太累了，先休息一下"}, nil
    }
    if _, err := t.pctx.AdjustStats(ctx, petID, pet.Stats{
        Energy: -t.EnergyCost, Happy: 5, EXP: 3,
    }); err != nil {
        return plugin.ToolResult{}, err
    }
    // 可选：t.pctx.DB().ExecContext(... 写入 training_logs ...)
    return plugin.ToolResult{OK: true, Outcome: "训练结束，感觉更有精神了"}, nil
}
```

然后：`Build` 注册 →（可选）config/YAML → `go test` → 重编译运行。

可选：再加一个 `skills/training-cheer/SKILL.md`，教宠物何时调用 `train`、如何口述结果（**不含数值公式**）。

## 6. 自检清单

- [ ] 只改了 `internal/plugins/<name>` + `builtins.go`（+ 如需 config），**没**改 `pet`/`tick`/`store` 领域规则来「开后门」
- [ ] 已在 `Build` 里显式注册（无目录自动发现）
- [ ] 数值走 `AdjustStats`/`Care`，事件走 `Emit`
- [ ] 持续活动走 `RegisterActivity` + `Apply`/`View`，不直接写 `Sleeping`
- [ ] 有表则实现了 `SchemaProvider`，表名有前缀
- [ ] 工具失败用 `OK: false`，不乱抛错
- [ ] `OnTick` / `OnEvent` 快速返回；`OnEvent` 不重入同宠 Engine
- [ ] 依赖：默认独立；硬用 `DependsOn`，软用 `HasPlugin` + 降级（勿为玩法绑死另一插件）
- [ ] HTTP 用 `httpx`，路径相对插件命名空间
- [ ] 有单测（可参考 adventure/friends 的 `setup` 模式）
- [ ] `go test ./internal/plugins/... ./internal/plugin/` 通过

## 7. 常见问题

**Q: 能自动注册吗？**  
A: **不能。** 必须改 `plugins.Build`。main 已不用改；也没有 blank import / `go:generate` 扫描。

**Q: 为什么改完要重编译？**  
A: 编译期注册，保证数值路径可信。Skill/MCP 才是热加载层。

**Q: 文档说「不改主程序」是什么意思？**  
A: 不改 `tick`/`store`/`pet` 领域层；装配在 `plugins.Build`，不是改玩法规则时去动 Engine。

**Q: 两只宠物对话怎么做？**  
A: 同实例跨宠用 `FindPetByName` + 工具（见 friends）；跨设备走 A2A，不是本插件框架职责。

**Q: 如何关某个玩法？**  
A: YAML `plugins.<name>.enabled: false` 后重启。
